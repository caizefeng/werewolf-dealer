# Werewolf Dealer – Development Guide

> **Keep this file up to date.** When the code, commands, rules or deployment change, update the
> relevant section here (and README.md for user-facing behaviour).

## What it is
Web dealer + judge for in-person 狼人杀 (sibling project of `../werewolf_viewer`, same visual
language). Players join a room by URL, pick seats, see their role on their phone; the server runs
nights/days with 京城大师赛 rules; the owner's phone plays the judge voice and night music.
UI text is Chinese. **Rules follow 京城大师赛**; README.md lists every judgement call.

## Commands
```bash
npm install
npm run dev          # server :3000 (watch) + vite :5173
npm test             # vitest (engine + server)
npm run typecheck    # tsc --noEmit (erasableSyntaxOnly: no enums/param properties/namespaces)
npm run build        # client → dist/client
npm run test:e2e     # playwright (builds, starts server with TIME_SCALE=0.3 TEST_HOOKS=1)
node scripts/smoke.ts <board> <base-url>                       # smoke test: 12 bots play night 1 on an instance
node scripts/loadtest.ts <base-url> --rooms 10 --minutes 8     # load test (rooms reused via --rooms-file; --cleanup after)
node scripts/find-overflow.mjs http://localhost:3000/ 375      # list elements wider than a phone
npm run build && node scripts/screenshots.ts [scene…]          # regenerate README screenshots (main lobby wolfgirl knight treasure)
deploy/deploy.sh     # deploy an instance (reads git-ignored deploy/deploy.env)
```
Node ≥ 22.18 runs `server/*.ts` directly (type stripping) – keep server/shared code to erasable TS
syntax and import with explicit `.ts` extensions.

## Engine conventions
- `Game` never reads the clock or Math.random: pass `now`; randomness from `rand(state)`.
  `tick(now)` advances timed phases; `nextWakeup()` tells the room when to tick.
- All durations go through `this.k` (ms per second × `scale`); `TIME_SCALE` env speeds games up.
- Night: steps come from the **config pool** (buried/dead roles are still called); non-interactive
  steps wait a random fake time; interactive ones wait ≥ `T.minAct`. Night deadlines are private.
- Night deaths are computed at dawn into `state.pending` and only applied when announced
  (after the day-1 election). Never expose pending deaths in any view.
- Day = queue of stages (`election`, `nightDeaths`, `discussion`, `exile`); 自爆 truncates it.
- 蒙面人: night deaths of a mask holder go to `state.wounded` (not `pending`); they die after their own
  discussion speech (`advanceSpeech`) or, if they never spoke, in `nextStage` before night falls.
  `maskedEarlyWin()` implements the ≥2-wolves early 屠神 settlement; `maskActiveEligible()` the
  盗宝蒙面 survival (a `mask` entry in the deathSkills phase, the death applied only if declined).
- Number swaps (魔术师 → 诡术师 → 狼术师): night records keep the numbers players picked; `nightPerm()`/`mapT()`
  map a number to the player actually hit, applied in `nightInputs` (settlement) and in any immediate
  result (查验, 假面验证). Every new targeted night skill must go through `mapT`.
- Knife holder chain (`knifeHolder`): pack → 机械狼 → 假面 → wolf-side 盗宝大师. `knifeAllowed()` (首夜禁刀)
  gates every knife on night 1.
- 狼女孩: `state.confession` (picked number, actual target, `turned` = 平民 → 狼混); `isLanghun()` changes only the
  win side (results); `revengeTarget()` is taken along by her 自爆. The `confessed` status step's actor is
  the confessed player (`stepActors`).
- 舞池/殉情 are settled in `resolveNight` (`extra`, `lovers`); `canShootFor` allows a gun only for knife/exile.
- 定序王子: every exile result goes through `exileOrPrince` (fixed window while the card is unused, even if
  the prince is dead); 骑士 duels only in `duelWindow()` (discussion/exilePk speeches); a won duel clears
  `dayQueue` and `resume`.
- Public audio/text must never include private info; tests assert this.
- Built-in bots: a seat whose client id starts with `bot:` (real ids can't contain `:`). The room plays them:
  `Room.planBots()` (run from `schedule()`, i.e. after every change and on restore) asks `botMove()` for each
  bot's next move, computed only from `room.view(botId)`, and arms one timer per bot keyed by the decision.
  The timer starts after the judge's voice ends, then waits the bot's thinking time. When it fires, the move is
  recomputed and applied only if the key still matches. A move the engine rejects is not retried. Decisions are seeded per
  (room, game, seat, decision), so re-planning never changes a choice. A new prompt kind or action needs a case in
  `server/bots.ts` and a test in `tests/server/bots.test.ts`; all-bot games must keep ending with no rejected move.
- Adding a role: `shared/roles.ts` (+ icon in `client/src/ui.tsx`), step in `stepsForNight`,
  `STEP_*` maps, prompt in `nightPrompt`, action in `nightAction`, settlement in `nightInputs`,
  clips in `shared/audio.ts` (then regenerate audio), tests, README rules section, and a case in
  `server/bots.ts` when the role brings a new prompt kind or needs smarter targets than a random pick.

## Audio
`scripts/gen_audio.py` (venv `scripts/.venv`, `pip install edge-tts`; needs node + ffmpeg) renders
every line in `shared/audio.ts` with `zh-CN-YunyangNeural`, trims/normalises, writes durations.
Only owner devices play audio; music is ducked to ~3% while the judge speaks.

## Deployment
- The repo is generic: users deploy their own instance (README "Deploy your own instance").
- **Never commit a real deployment's hostnames, IPs, domains, SSH users or server notes** – not in
  code, docs, comments, tests or commit messages. They live only in git-ignored files:
  `deploy/deploy.env` (read by `deploy/deploy.sh`) and `CLAUDE.local.md` (machine-specific notes).
  Use `werewolf.example.com` / `user@your-server` in anything tracked.
- `deploy/deploy.sh`: rsync to `$DEPLOY_DIR` → `HOST_PORT=… docker compose up -d --build` (container
  `werewolf-dealer`, volume `werewolf-data`) → renders `deploy/werewolf.caddy.template` into
  `$CADDY_SITE`, validates `$CADDYFILE` (restores the old file on failure) → `systemctl reload caddy`
  → health checks.
- Logs: `docker logs -f werewolf-dealer`; health: `/api/health`.
- Instances stay out of search engines (`server/index.ts`): `/robots.txt` disallows all, every response has
  `X-Robots-Tag: noindex…` (plus the `robots` meta in `client/index.html`), and `isCrawler()` user agents get 403
  except on `/robots.txt` and `/api/health`. Chat link previews (`PREVIEW_UA`) and phones must stay allowed;
  `tests/server/server.test.ts` checks real user-agent strings for both sides.
